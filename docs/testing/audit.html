High severity

H1High
One policy appears in many worklists at once

A single active, unpaid policy shows simultaneously in Collections (unpaid), Follow-up → no_commission / not_delivered, and — if life — Freelook. The TST-RC* receipt-test policies even surface in Collections as "cash unpaid ฿10,000".

Why it matters: staff can't tell which worklist owns a policy; the same item gets chased by several people. There's no cross-list dedup or "handled elsewhere" signal.

Suggestion → a per-policy worklist state that suppresses a row once actioned, or at minimum show which other lists a policy is currently in.

H2High
"no_commission" fires on ~458 of ~475 policies

The rule is active AND (carrier→hub OR hub→agent amount is null/0). Because commission amounts are mostly 0 in real data, almost every policy matches.

Why it matters: a worklist containing "nearly everything" isn't actionable — it's noise that buries the genuinely-missing ones.

Suggestion → scope it (only policies past an age, or where the product should carry commission), or split "never had commission" from "commission not yet entered".

Medium severity

M1Medium
Team assignment is invisible and unguided

Every seeded agent shows TEAM = —. The create/edit form has a สายงาน/team field, but nothing prompts assignment, and MGM team-volume logic depends on it. New agents silently have no team.

Suggestion → surface team on the create form; add a "no team assigned" badge on the hub.

M2Medium
Commission shows ฿0 across most of the UI

Payout preview, receipt expected amounts, and dashboard KPIs read ฿0 for most policies because the commission columns and policy_rebates are unpopulated. The features are correct, but a first-time user sees "฿0 everywhere" and assumes it's broken.

Suggestion → an empty-state hint, and/or a way to compute commission from the product rate in bulk.

M3Medium
Payout eligibility diverges from the Access spec's filter

The legacy spec gated on Freelook_Status = TRUE and Payment_InsComp_Status NOT IN ('2','5'). The web payout uses status ∈ (active, issued) + not-paid + not-in-live-batch, but skips the freelook and insurer-payment gates.

Suggestion → confirm with finance whether those gates still apply; document the divergence if intentional.

M4Medium
Receivables are created lazily and invisibly

Insurer-receipt rows exist only after someone opens a Main/OV tab for a Year+Insurer. Before that, History and the Dashboard are empty despite hundreds of eligible policies — a manager opening the Dashboard first sees nothing.

Suggestion → materialise receivables on a schedule, or show Dashboard "potential" figures from the underlying policies before rows exist.

M5Medium
Two different meanings of vat_type

agents.vat_type is ''|none|vat7|wht* in the agent form, but the payout engine reads it as numeric '1'|'2'|'3'. An agent created through the form carries no numeric value, so its VAT PDF defaults to "no VAT" regardless of has_vat/vat_mode.

Empirical: 324 agents have numeric vat_type='1' (legacy import) but 52 have empty '' — those are the ones at risk.

Suggestion → make the payout read has_vat + vat_mode instead of the legacy numeric field, or map between them explicitly.

Low / polish

L1Low
Cancelled exclusion — verified OK

Confirmed cancelled policies are excluded from no_commission and not_delivered (queries scope to status='active'). No action needed.

L2Low
Collections paid fallback can double-count

paid = SUM(policy_payments), with a total_premium_paid fallback only when zero rows. If both are populated on a real policy, verify there's no double count. (A non-idempotent seeder insert exposed this during testing — fixed in the seeder.)

L3Low
Freelook follow-up has no inline date entry

Correct per spec, but you must open the full policy editor to set the freelook date. An inline date field on the follow-up row would speed the chase.

L4Low
Receipt page History is empty on a fresh DB

The page now defaults to History (good), but History stays empty until Main/OV seed rows. A first-run hint would explain the emptiness.

L5Low
Payout PDF filename collisions

Filenames use the agent's display name, truncated at 120 chars. The ZIP path dedups duplicates; the single-download path does not — verify no collision for agents sharing a code prefix.
