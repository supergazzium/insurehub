## 3. การไหลของข้อมูล (7.2)

```
แก้ชนิด / VAT / โหมด / เลขภาษี ในฟอร์ม
   └─ ตรวจในหน้า (ชื่อนิติบุคคล, เลขภาษี) → dialog เดิม→ใหม่ + ยอดค้าง (GET commission-payout-batches/by-agent/{id})
   └─ PATCH /agents/{id}
        AgentRequest: นิติบุคคล → juristicName + taxId · มี VAT → taxId + vatMode · taxId เปลี่ยน → 13 หลัก + checksum
        toModel: sync vat_type = 1 ไม่มี / 2 ไม่รวม / 3 รวม
        AgentObserver: audit agent.updated {fields, old, new} (tax_id ปิดบังเหลือ 4 ตัวท้าย) + user + ip

สร้างรอบจ่าย (CommissionPayoutService::createBatch)
   batch item เก็บ vat_type + payee_name (นิติบุคคล = ชื่อนิติบุคคล) + payee_kind + payee_tax_id
   show / PDF / CSV ของรอบนั้นอ่านจาก snapshot → แก้ตัวแทนภายหลังไม่กระทบ · รอบใหม่ใช้ค่าปัจจุบัน
```

## 9. ข้อจำกัด / งานต่อ

- **ยังไม่มีการหัก ณ ที่จ่าย (1%/3%)** ในระบบจ่ายค่าคอม — ตอนนี้ชนิดบุคคล/นิติบุคคลมีผลแค่ชื่อและเลขภาษีผู้รับบนเอกสารจ่าย ถ้าต้องหักภาษีต้องทำเป็นงานแยก
- **ข้อมูลเดิมมีบริษัทถูกเก็บเป็นบุคคลธรรมดาประมาณ 17 ราย** (ชื่อขึ้นต้น "บริษัท…" หรือเลขภาษีขึ้นต้น 0 เช่น IN210013, IN220282) — ไม่ได้แก้อัตโนมัติ ให้แอดมินตรวจและเปลี่ยนเป็นนิติบุคคลระหว่าง UAT
- การอนุมัติ/ปฏิเสธ "ตัวแทนสมัครใหม่" ในแถบรออนุมัติของหน้ารายการยังใช้ `window.prompt` (หน้าดูข้อมูลใช้กล่องเหตุผลแล้ว)
