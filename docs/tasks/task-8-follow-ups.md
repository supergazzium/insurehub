## 1. สรุป

| เรื่อง | ผลลัพธ์ |
|---|---|
| 8.1 ยังไม่ชำระ + ตัวนับ + อายุงาน | หน้า "ติดตามงานค้าง" มี **8 หมวด** พร้อมตัวเลขทุกหมวด (เพิ่ม **ยังไม่ชำระเงิน** และ **รอ Verify**) · ทุกแถวมี **อายุงานค้าง (วัน)** · แถบกรอง **0-7 / 8-30 / เกิน 30 วัน** พร้อมจำนวน · เรียงงานที่ค้างนานสุดก่อน · หมวดที่เลือกจำไว้ใน URL (`?cat=`) |
| 8.1 ยังไม่ชำระ | กรมธรรม์มีผล/ออกแล้วที่มีงวดถึงกำหนดแต่ยังไม่ชำระ · แสดง **ยอดค้าง, จำนวนงวด, วันครบกำหนดเก่าสุด** (นับอายุจากงวดเก่าสุด) |
| 8.1 กติกาหมวดอื่น | ยังไม่จัดส่ง = ยังไม่มีวันจัดส่ง (ใช้ `shipped_date` หรือ `mailing_date` ของข้อมูลเก่า) + ขั้น "ส่งแล้ว ลูกค้ายังไม่ได้รับ" · ยังไม่บันทึกค่าคอม = นับ **180 วันจากวันเริ่มคุ้มครอง** (เดิมนับจากวันคีย์ ข้อมูล import ติดหมด 340 → เหลือ 125) ตั้งค่าได้ |
| 8.2 Freelook | วันสิ้นสุด Freelook **คำนวณอัตโนมัติ = วันที่ลูกค้าได้รับ + 15 วัน** (ขายทางโทรศัพท์/ออนไลน์ **+ 30 วัน**) ตั้งค่าได้ · เพิ่ม **ช่องทางการขาย** · ติดตามเอกสาร 3 ขั้น **ส่ง → ลูกค้าเซ็น → ส่งคืนบริษัท** (ปุ่ม "วันนี้" ในหน้าติดตาม หรือกรอกวันในฟอร์ม) · หมวดนี้เฉพาะ **ประกันชีวิตที่มีผล/ออกแล้ว** (ไม่ปนร่าง/ยกเลิก) · ขั้นย่อย: ยังไม่ส่งเอกสาร / ส่งแล้วยังไม่ได้คืน / **ใกล้ครบ Freelook (≤ 7 วัน)** / ยังไม่มีวันลูกค้าได้รับ |
| 8.3 ตรวจรายการยกเลิก | ปุ่ม "ตรวจสอบ" เปิดแผง: วันยกเลิก, ยอดคืนเบี้ย, **ยอดเรียกคืนค่าคอมตัวแทน** (แนะนำจากค่าคอมที่จ่ายไปแล้ว), checklist 3 ข้อ (คืนเบี้ย / เรียกค่าคอมคืน / บ.ประกันหักค่าคอมเรา) เลือก เสร็จแล้ว·ไม่เกี่ยวข้อง·ยังไม่ · **กด "ตรวจแล้ว" ได้เมื่อไม่มีข้อ "ยังไม่"** · ตรวจแล้วหายจากรายการ (ดูย้อนได้ที่ "ตรวจแล้ว") · มี audit |
| 8.3 Clawback | ยอดเรียกคืนค่าคอม → **หักอัตโนมัติในรอบจ่ายค่าคอมถัดไปของตัวแทน** หักได้ไม่เกินยอดที่จะจ่าย ส่วนที่เหลือ **ยกไปรอบหน้า** · หน้าจ่ายค่าคอมแสดง "หักเรียกคืนค่าคอม" + "ยอดจ่ายสุทธิ" + รายการหักค้าง · ยกเลิกรอบจ่าย = ยอดหักกลับมารอหักใหม่ |
| 8.4 ออกแบบ Maker-Checker | เลือกแบบ **"คำขอเปลี่ยนแปลงรอตรวจ"** — ข้อมูลจริงไม่เปลี่ยนจนกว่าคนที่ 2 อนุมัติ · รายละเอียด [`verify-design.md`](task-8-follow-ups/verify-design.md) |
| 8.5 Verify กรมธรรม์ | เปิด/ปิดได้ที่ **ตั้งค่าหน่วยงาน › ติดตามงาน & Verify** (ค่าเริ่มต้น **ปิด**) · เมื่อเปิด: สร้างกรมธรรม์ (ร่าง → สถานะจริง), แก้ **ช่องสำคัญ**, และ **ลบ (ทุกสถานะ ต้องใส่เหตุผล)** กลายเป็นคำขอ · ช่องงานประจำ (หมายเหตุ, การจัดส่ง, Freelook ฯลฯ) บันทึกทันที · ผู้ส่งอนุมัติเองไม่ได้ · ต้องมีสิทธิ์ `policies.verify` |
| 8.6 คิว Verify + diff | หมวด "รอ Verify" ในหน้าติดตาม (แท็บ **รอตรวจ** / **คำขอของฉัน**) · หน้ารายละเอียดคำขอแสดง **diff ทีละช่อง (แดง = เดิม, เขียว = ใหม่)** หรือข้อมูลสำคัญทั้งชุดสำหรับคำขอสร้าง/ลบ · อนุมัติ / ไม่อนุมัติ (**บังคับเหตุผล**) · ผู้ส่งเห็นสถานะ + เหตุผล และ **ถอนคำขอ** ได้ |

**การตัดสินใจ (ยืนยันกับผู้ใช้):** Verify แบบคำขอรอตรวจ (ข้อมูลจริงไม่เปลี่ยน, กรมธรรม์ใหม่ค้างเป็นร่าง) · ตรวจเฉพาะช่องสำคัญ · ปิดไว้ก่อน เปิดที่ตั้งค่าหน่วยงาน · ขอลบได้ทุกสถานะเมื่อเปิด verify · Freelook = วันลูกค้าได้รับ + 15 วัน (โทรศัพท์/ออนไลน์ 30 วัน) ตั้งค่าได้ · ยังไม่บันทึกค่าคอม = 180 วันจากวันเริ่มคุ้มครอง ตั้งค่าได้ · Clawback หักอัตโนมัติรอบถัดไป + ยกยอด · "ตรวจแล้ว" ต้องไม่มีข้อ "ยังไม่"

## 2. ปัญหาที่พบก่อนแก้

| # | ปัญหา | สาเหตุ |
|---|---|---|
| B1 | หน้าติดตามมี 6 หมวด ไม่มี "ยังไม่ชำระ" ไม่มีอายุงานค้าง | — |
| B2 | "ยังไม่บันทึกค่าคอม" 340 รายการ | นับ 180 วันจาก `created_at` → ข้อมูลที่ import วันเดียวกันติดหมด |
| B3 | Freelook ต้องกรอกวันสิ้นสุดเอง · รายการมีร่าง/ยกเลิก/รออนุมัติปน · ไม่มีที่ติดตามเอกสาร | เงื่อนไขแค่ `freelook_end_date` ว่าง ไม่ดูสถานะ |
| B4 | รายการยกเลิกแสดงทุกรายการตลอด ไม่มีสถานะ "ตรวจแล้ว" ไม่มีวันที่ | ไม่มีคอลัมน์ตรวจสอบ |
| B5 | แก้กรมธรรม์บันทึกลงข้อมูลจริงทันที ไม่มีคนตรวจ | ไม่มีระบบ Verify |

**บั๊กอื่นที่แก้ไปด้วย:**
- "ยังไม่จัดส่ง" ไม่รู้จักวันจัดส่งของข้อมูลเก่าที่เก็บใน `mailing_date` ทำให้รายการเกินจริง (453 → 112)
- อายุงานคำนวณจากวันของฐานข้อมูล ไม่ใช่วันของแอป
- หน้าจ่ายค่าคอมของตัวแทนขึ้น "ไม่พบข้อมูลตัวแทน" เมื่อตัวแทนไม่มีค่าคอมค้าง แต่มียอดหักค้าง
- ผู้ใช้ทุกคนแก้ตั้งค่าหน่วยงานได้: ส่วนติดตามงาน & Verify ตอนนี้ต้องมีสิทธิ์ `admin.settings` (กันผู้คีย์ปิด verify เอง)

## 3. การไหลของข้อมูล

```
ติดตามงานค้าง  GET /follow-ups?category=&aging=0-7|8-30|30+&stage=&reviewed=1
   └─ meta: counts (8 หมวด), aging (3 ช่วง), stages (ขั้นย่อย), verifyEnabled, noCommissionWindowDays

Freelook
   Policy::saving  ถ้าเปลี่ยน delivered_date / sales_channel / product → Freelook::apply
                   ประกันชีวิต + มีวันได้รับ → freelook_end_date = delivered_date + (โทร/ออนไลน์ ? 30 : 15)
   PATCH /policies/{id}/freelook {sentAt, signedAt, returnedAt}  (บังคับลำดับ ส่ง ≤ เซ็น ≤ คืน, event freelookDocUpdated)

ตรวจยกเลิก
   PATCH /policies/{id}/cancellation-review {refundAmount, clawbackAmount, checks, note, cancelDate, markReviewed}
     └─ markReviewed + มีข้อ pending → 422
     └─ clawbackAmount > 0 → commission_payout_adjustments (type clawback, status pending, ไม่ผูกรอบ)
   สร้างรอบจ่าย (createBatch / payAgent) → applyPendingDeductions
     └─ หักได้ ≤ ค่าคอมของตัวแทนในรอบ · ที่เหลือแตกเป็นแถว pending ใหม่ (ยกไปรอบหน้า)

Verify (เมื่อ tenants.policy_verify_required = 1)
   PATCH /policies/{id} · PATCH /policies/{id}/draft · POST promote-to-submitted · POST events · POST issue · DELETE
     └─ ช่องสำคัญเปลี่ยน / ร่าง → สถานะจริง / ลบ → pending_changes + ตอบ 202 {data, meta.pendingChange}
     └─ ช่องงานประจำบันทึกทันที
   POST /verifications/{id}/approve  → maker ≠ checker → apply ผ่านเส้นทางเดิม (observer / งวด / event ทำงานตอนนี้)
   POST /verifications/{id}/reject {reason} · POST /verifications/{id}/cancel (ผู้ส่งเท่านั้น)
```

## 4. API / ฐานข้อมูล

Migration `2027_03_21_000100_follow_up_mode`
- `policies`: `sales_channel` (face_to_face|telephone|online), `freelook_doc_sent_at / signed_at / returned_at`, `cancellation_reviewed_at`, `cancellation_reviewed_by_user_id`, `refund_amount`, `commission_clawback_amount`, `cancel_check_refund / clawback / carrier_deduct` (pending|done|na), `cancel_review_note`
- `tenants`: `policy_verify_required` (ปิด), `freelook_days_standard` (15), `freelook_days_remote` (30), `no_commission_window_days` (180)
- `commission_payout_adjustments`: `batch_id` เป็น nullable, เพิ่ม `policy_id`, `status` (pending|applied), `applied_at`
- ตารางใหม่ `pending_changes` (entity, action create|update|delete, payload, before, fields, status, maker, checker, decided_at, reason, note)
- สิทธิ์ใหม่ `policies.verify` "ตรวจสอบ (Verify) กรมธรรม์" (admin / super_admin มีอยู่แล้ว)

Endpoint ใหม่: `PATCH policies/{id}/freelook` · `GET|PATCH policies/{id}/cancellation-review` · `GET verifications` (`scope=pending|mine|all`) · `GET verifications/{id}` · `POST verifications/{id}/approve|reject|cancel`

`PolicyResource` เพิ่ม `salesChannel`, `freelookDoc*`, `verification {pending, lastRejected}`, `cancellationReview` · `TenantResource` เพิ่มค่าตั้ง 4 ค่า · หน้าจ่ายค่าคอมเพิ่ม `pendingDeductions`, `totals.pendingDeduction`, `totals.netAmount`, `byAgent[].pendingDeduction`
