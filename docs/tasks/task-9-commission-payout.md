## 2. ปัญหาที่พบก่อนแก้

| # | ปัญหา | สาเหตุ |
|---|---|---|
| B1 | หน้าทำจ่ายเห็นแต่ผู้ขาย upline ที่มีค่าแนะนำ/ค่าบริหารใน ledger ไม่ขึ้นเลย (TST-A02 ฿4,300, TST-A01 ฿860 ไม่เคยจ่าย) | payout อ่านแต่ยอดในกรมธรรม์ |
| B2 | จ่ายกรมธรรม์ที่ลูกค้ายังไม่ชำระ / บริษัทยังไม่จ่ายค่าคอมเราเต็มจำนวน | ตัดเงื่อนไขออกโดยตั้งใจ (audit M3) |
| B3 | รอบจ่ายไม่มีหัก ณ ที่จ่าย ไม่มี 50 ทวิ ไม่มีไฟล์โอน · VAT คิดตอนออก PDF ไม่ได้เก็บ | ไม่มีโค้ดส่วนนี้ |
| B4 | PDF เป็นตัวหนังสือ "InsureHub" ไม่มีโลโก้/ข้อมูลบริษัท · ปุ่ม PDF รายคนเปิดแล้ว 401 | `window.open` ไม่ส่ง token |

**บั๊กอื่นที่แก้ไปด้วย:**
- engine คิดฐานค่าคอมต่อการชำระ `min(ยอด, เบี้ยสุทธิ)` ไม่สะสม → กรมธรรม์ผ่อนคิดเกิน · แก้เป็นใช้ `net_amount` และสะสมไม่เกินเบี้ยสุทธิ · เก็บ `mgmt_fee_amount` แยก
- ลบการชำระแล้ว ledger ถูกลบตาม (cascade) แม้จ่ายไปแล้ว → ตอนนี้ห้ามลบการชำระที่ค่าคอมอยู่ในรอบจ่าย (409)
- สร้างรอบพร้อมกันจ่ายซ้ำได้ → ล็อกแถว tenant + batch ทุกขั้น และผูก ledger แบบตรวจจำนวนแถว
- ยกเลิกรอบหลังหักบางส่วน → มียอดเรียกคืนค้าง 2 แถว แก้ไขได้แถวเดียว (หักเกิน) → รวมเป็นแถวเดียว
- กรมธรรม์ถูกยกเลิกหลังเข้ารอบแล้วยังถูกจ่าย → ตอนยืนยันจ่ายระบบนำออก คืน ledger และให้อนุมัติใหม่
- พอร์ทัลรายได้ตัวแทนอ่านตาราง `commission_transactions` ที่ถูกลบ → error
- endpoint จ่ายค่าคอมไม่ตรวจสิทธิ์ · แท็บ "รอบการจ่ายเงิน" ในตั้งค่าเป็น mock ไม่บันทึกจริง

## 3. การไหลของข้อมูล

```
ลูกค้าชำระ (PolicyPayment) → MgmCommissionEngine
   DIRECT (ฐาน + ค่าบริหารผู้ขาย → mgmt_fee_amount) · REFERRAL_FEE · MANAGEMENT_DIFFERENTIAL  → commission_ledgers

หน้าทำจ่าย → CommissionPayoutService::collectLines
   base      : resolveAmount ต่อกรมธรรม์ × สัดส่วนงวดที่ชำระ − ที่จ่ายไปแล้ว
   self_mgmt : DIRECT.mgmt_fee_amount > 0         ┐
   referral  : REFERRAL_FEE                       ├ ledger ที่ยังไม่ผูกรอบ (payout_batch_id IS NULL)
   override  : MANAGEMENT_DIFFERENTIAL > 0        ┘
   PayoutEligibility (ต่อกรมธรรม์): Freelook / รับค่าคอมจากบริษัท / ลูกค้าชำระ / override → ready | waiting(+เหตุผล)

createBatch (ล็อก tenant) → items (line_type, ledger_id, paid_ratio, entitlement) + ผูก ledger
   → หัก: เรียกคืน (pending) → ค่าผ่อนที่ตัวแทนรับภาระ (INSTALLMENT_AGENT_COST ทั้งแถว) → หักพิเศษ (เพิ่มในรอบ)
   → commission_payout_payees: แยกยอดตามประเภท · VAT · WHT · สุทธิ · บัญชีธนาคาร (encrypted)
approve → แช่แข็งยอดผู้รับ · markPaid → ตรวจกรมธรรม์ยกเลิก → ledger settled → 50 ทวิ เลขรัน (tax_cert_sequences)
```

## 4. API / ฐานข้อมูล

Migration `2027_03_22_000100_commission_payout_v2`
- `commission_payout_batches.calc_version` (1 = รอบเดิม, 2 = ใหม่) — รอบเดิมแสดง/PDF แบบเดิม ไม่เข้ารายงาน ภ.ง.ด.
- `commission_payout_batch_items`: `line_type`, `ledger_id`, `source_agent_id`, `paid_ratio`, `entitlement_amount`, `ratio_label`, `condition_override`
- `commission_ledgers`: `payout_batch_id`, `paid_at`, `mgmt_fee_amount` (+ backfill)
- `commission_payout_adjustments.ledger_id` · ตารางใหม่ `commission_payout_payees`, `tax_cert_sequences`, `policy_payout_overrides`
- `tenants`: `payout_require_freelook / _insurer_received / _customer_paid`, `wht_rate_individual / _corporate` · `agents.wht_rate`
- สิทธิ์ `payouts.*` ให้บทบาท finance (migration + `RbacPermissionSeeder`)

Endpoint ใหม่: `GET commission-payout-batches/wht-report?month=&form=pnd3|pnd53[&format=csv]` · `GET …/{batch}/bank.csv` · `GET …/{batch}/payees/{payee}/certificate` · `POST|DELETE policies/{policy}/payout-override` · `GET me/agent/payouts/{batch}/statement|certificate` · PDF ทุกตัวรองรับ `?as=base64`
คำสั่ง: `php artisan payouts:settle-ledger-before {YYYY-MM-DD} [--dry-run]` — ปิดยอด ledger เก่าที่จ่ายนอกระบบไปแล้ว (ใช้ตอนขึ้นระบบจริง)
