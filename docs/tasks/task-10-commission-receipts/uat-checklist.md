# UAT — รับค่าคอมจากบริษัทประกัน (งาน 10.1)

ผู้ทดสอบ: ฝ่ายบัญชี · ระบบ: InsureHub → รับค่าคอม · ใช้ statement จริงของ 1 เดือน จาก 2–3 บริษัทประกัน

## ก่อนเริ่ม

- [ ] ผู้ทดสอบมีสิทธิ์ "ดูการรับค่าคอม" และ "บันทึกรับค่าคอม" (บทบาทการเงินได้อยู่แล้ว) · หัวหน้าบัญชีมีสิทธิ์ "เปิดรายการรับค่าคอมที่รับแล้วกลับมาแก้"
- [ ] เลือก statement จริง 1 เดือนของ 2–3 บริษัท เตรียมไฟล์ Excel ที่มีคอลัมน์เลขกรมธรรม์ (หรือเลขใบคำขอ) และยอดค่าคอม
- [ ] จดยอดรวมของแต่ละ statement ไว้เทียบ

## ขั้นตอนต่อบริษัท

1. แท็บ "ค่าคอมหลัก" เลือกบริษัทประกัน และเดือนเริ่มคุ้มครองให้ตรงกับ statement (ติ๊ก "รวมรายการค้างจากเดือนก่อน" ไว้)
2. กด "วางยอดจาก Excel" คัดลอก 2 คอลัมน์ (เลขกรมธรรม์ + ยอด) จาก statement มาวาง แล้วกด "ตรวจจับคู่"
3. จดรายการที่ "ไม่พบในระบบ" / "เป็นของบริษัทอื่น" / "รับไปแล้ว" ลงตารางเคสด้านล่าง แล้วกด "บันทึกยอดตามบริษัท"
4. ตรวจแถวที่ "ยอดไม่ตรง" ดูป้ายข้อสังเกต (ยกเลิก / สลักหลัง / ไม่มีค่าคอมในกรมธรรม์ / อัตราไม่ตรง) และเปิดดูรายละเอียดกรมธรรม์ถ้าจำเป็น
5. ติ๊กเลือกรายการที่ได้รับเงินแล้ว กด "ยืนยันรับเงิน" ใส่วันที่รับ สร้างรอบ statement ใหม่ (เดือน + ยอดรวม statement) เลือกสาเหตุทุกแถวที่ยอดต่าง
6. ถ้า statement มียอดเพิ่ม/หักคืนของกรมธรรม์ที่รับไปแล้ว ให้เปิดกรมธรรม์นั้น → "เพิ่มรายการปรับปรุง" (สลักหลัง / ยกเลิก-บริษัทหักคืน / อื่นๆ) แล้วยืนยันรับ
7. แท็บ "รอบ statement" ตรวจว่ายอดรับในระบบ = ยอด statement (ส่วนต่าง 0) ถ้าไม่เท่าให้หาสาเหตุ
8. แท็บ "สรุปผล" ดูการ์ด "สรุปเคสยอดไม่ตรงตามสาเหตุ" และกด "ส่งออก CSV" ที่แท็บประวัติเก็บไว้แนบผล UAT

| # | รายการ | ผ่าน/ไม่ผ่าน |
|---|---|---|
| 1 | รายการที่ระบบเรียกขึ้นมาครอบคลุมทุกกรมธรรม์ใน statement (ไม่พบในระบบ = 0 หรืออธิบายได้) | |
| 2 | ยอดที่ควรได้ของกรมธรรม์ที่ไม่มีปัญหาตรงกับ statement | |

| 4 | กรมธรรม์ยกเลิก / สลักหลัง แสดงป้ายถูกต้อง และยอดประมาณการใกล้เคียงยอดบริษัท | |

## ตรวจ audit L2 กับข้อมูล production (ผู้ดูแลระบบ)

1. บนเครื่อง production รัน `php artisan collections:audit-payments --csv=storage/app/audit-payments.csv` (อ่านอย่างเดียว ไม่แก้ข้อมูล)
2. ส่งไฟล์ CSV ให้ฝ่ายบัญชี ตรวจหมวด: ชำระเกิน · รายการซ้ำ · รายการนำเข้า + ชำระจริง · รายการนำเข้าบนกรมธรรม์ระบบใหม่
3. หมวด "กรมธรรม์ระบบใหม่ที่ยังไม่ชำระ ซึ่งเคยถูกซ่อน" ให้ฝ่ายติดตามเงินตรวจว่ายังค้างจริงหรือไม่
4. ห้ามรัน `payments:backfill-legacy` บน production ก่อนตรวจผลข้อ 2
