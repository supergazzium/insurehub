# งาน 11 — บันทึกการชำระเงินในหน้าแก้ไขกรมธรรม์ (บันทึกลง DB จริง เชื่อมระบบอื่นจริง)

ที่มา: คำขอจากผู้ใช้ ณ หน้า `/policies/:id/edit-draft` ส่วน "บันทึกการชำระเงิน" · ทำเมื่อ 2026-10-04 · ไม่ใช่งานใน ClickUp

> ให้ปุ่ม "บันทึกการชำระเงิน" ใช้งานจริง: บันทึกลงฐานข้อมูล เชื่อมกับตารางงวด ค่าคอม ติดตามเงิน รอบจ่าย และรายงาน · วางแผนให้ถูกหลักและใช้ง่ายสำหรับผู้ใช้

## 1. สรุป

| เรื่อง | ผลลัพธ์ |
|---|---|
| หน้าแก้ไขกรมธรรม์ | ส่วน **การชำระเงิน** แสดงป้ายสถานะ (ยังไม่ชำระ / ชำระบางส่วน / ชำระครบแล้ว / ชำระเกินยอด / ระบบเดิม) · การ์ดสรุป **เบี้ยที่ต้องชำระ / ชำระแล้ว / ค้างชำระ** · แยกยอด "เข้า InsureHub" กับ "จ่ายตรงบริษัทประกัน" · **ตารางประวัติ**: วันที่ งวด จำนวน ช่องทาง ผู้รับชำระ เลขอ้างอิง หมายเหตุ ปุ่มดูสลิป ผู้บันทึก · รายการที่ยกเลิกยังแสดง (ขีดฆ่า + เหตุผล + ผู้ยกเลิก) แต่ไม่นับในยอด |
| ช่องกรอก (modal) | ยอดที่ต้องชำระมาจากระบบ (ตัวคำนวณเดียวกับหน้าติดตามเงิน) · ช่อง "เงินที่ได้รับจริง" ถูกเติมเป็นยอดค้างให้ · แนบสลิปจริง (JPG/PNG/WEBP/PDF ไม่เกิน 10 MB) · เลขอ้างอิง · หมายเหตุ · วันที่ห้ามอนาคต · ชำระให้ InsureHub / บริษัทประกัน · ข้อความผิดพลาดเป็นภาษาไทยที่บอกว่าต้องทำอะไร |
| สถานะที่รับเงินได้ | ทุกสถานะ **ยกเว้นยกเลิก / หมดอายุ** (ลูกค้ามักจ่ายก่อนบริษัทประกันออกกรมธรรม์) · ปุ่มถูกปิดพร้อมเหตุผลบนหน้า · รับเงินกับกรมธรรม์ `issued` แล้วเปลี่ยนเป็น `active` อัตโนมัติ |
| ยกเลิกรายการ | **ไม่ลบจริง** — ใส่เหตุผล (บังคับ) · ตัดออกจากยอดชำระ ยอดงวด ยอดขายสะสม และย้อนค่าคอมที่ยังไม่เข้ารอบจ่าย (`reversed`) · ถ้าค่าคอมเข้ารอบจ่ายแล้ว ยกเลิกไม่ได้ (409) · บันทึกเหตุการณ์ในไทม์ไลน์กรมธรรม์ · บันทึกใหม่ซ้ำหลังยกเลิกได้โดยค่าคอมไม่เพี้ยน |
| จ่ายหักคอมมิสชั่น | ยอดที่รับ + ค่าคอมที่ตัวแทนหัก = เบี้ยเต็ม (ลูกค้าไม่ค้าง) · ค่าคอมตัวแทนคิดจากเบี้ยเต็ม · สร้างแถวหักค่าคอม (ติดลบ) **หักออกจากรอบจ่ายของตัวแทนอัตโนมัติ** ไม่จ่ายซ้ำ (หักไม่ครบรอบนี้ ยกไปรอบหน้า) · ห้ามหักเกินค่าคอมตัวแทนของกรมธรรม์ |
| จ่ายมีส่วนลด | ยอดที่รับ + ส่วนลด = เบี้ยเต็ม · ส่วนลดไม่นับเป็นยอดขายสะสม |
| จ่ายตรงบริษัทประกัน | นับเป็นเบี้ยที่ชำระแล้ว (ลูกค้าไม่ค้าง ค่าคอมคำนวณตามปกติ) · มีป้ายและแยกยอดในหน้าสรุปและรายงานประวัติการชำระ |
| สิทธิ์ | `payments.record` บันทึก · `payments.void` ยกเลิกรายการ · admin/finance ได้ทั้งสอง · sales_support / operations บันทึกได้ · ไม่มีสิทธิ์ → ปุ่มปิดพร้อมคำอธิบาย และ API ตอบ 403 (เดิมใครล็อกอินก็บันทึก/ลบได้) |

**การตัดสินใจ (ยืนยันกับผู้ใช้ — ทั้งหมดตามที่แนะนำ):** รับเงินได้ทุกสถานะยกเว้นยกเลิก/หมดอายุ · ยกเลิกพร้อมเหตุผลเก็บรายการไว้ + สิทธิ์ใหม่ `payments.void` · หักคอม = เบี้ยครบและตัดค่าคอมที่หักแล้วออกจากรอบจ่าย · จ่ายตรงบริษัทนับเป็นเบี้ยที่ชำระแล้วแต่แยกป้าย/ยอดในรายงาน

## 3. การไหลของข้อมูล

```
หน้าแก้ไขกรมธรรม์ ── แผงการชำระเงิน (PolicyPaymentPanel)
   GET  /policies/{id}/payments?withVoided=1  → รายการ + meta {due, paid, outstanding, toInsureHub, toCarrier,
                                                 status, payable, blockedReason, canRecord, canVoid}
   POST /policies/{id}/payments               → modal (อัปโหลดสลิป POST documents/upload type=receipt ก่อน แล้วส่ง proofDocumentId)
   POST /policies/{id}/payments/{pid}/void    → เหตุผลบังคับ

บันทึกชำระ (PolicyPaymentService::record — ทรานแซกชันเดียว ล็อกแถวกรมธรรม์)
   ├─ ตรวจสถานะ (ยกเลิก/หมดอายุ → 422 policy_not_payable) · สิทธิ์ payments.record
   ├─ กันซ้ำ (วัน+ยอดเดียวกันใน 10 นาที → 409 ถามยืนยัน) · กันเกินเบี้ย (409 ถามยืนยัน; นับ ยอดรับ + ส่วนลด/ค่าคอมที่หัก)
   ├─ policy_payments (+payee, pay_mode, note, adjustment_amount/kind, proof_document_id)
   ├─ PolicyPaymentInstallmentObserver → ตารางงวด (นับยอดรับ + ส่วนปรับ)
   ├─ PolicyPaymentObserver → ยอดขายสะสม (VolumeAccumulator) → เลื่อนขั้น → ค่าคอม (MgmCommissionEngine; ฐาน = เบี้ยเต็มเมื่อหักคอม)
   ├─ หักคอม → commission_ledgers COMMISSION_PAID_AT_SOURCE (ติดลบ, ตัวแทน) → CommissionPayoutService หักในรอบจ่าย (รายการหักค้าง)
   ├─ ค่าผ่อนที่ตัวแทนรับภาระ (InstallmentAgentCost) ไม่ลงซ้ำเมื่อบันทึกใหม่หลังยกเลิก
   ├─ policy_events: premiumPaid · issued → active
   └─ ตอบ 201 พร้อม meta ล่าสุด → แผงรีเฟรช + หน้ารีเฟรชสถานะกรมธรรม์ (ไม่ยิง autosave ซ้ำ)

ยกเลิกรายการ (PolicyPaymentService::void)
   ล็อกแถว → ค่าคอมของรายการนี้อยู่ในรอบจ่าย/ settled แล้ว? → 409 payment_commission_paid
   ไม่ใช่ → voided_at/by/reason · ledger unsettled → reversed (ยกเว้นค่าผ่อนระดับกรมธรรม์) · observer คำนวณงวด/ยอดขายสะสม/เลื่อนขั้นใหม่ · event premiumPaymentVoided

ผู้อ่านยอดชำระที่กรอง voided แล้ว: PremiumDue (หน้าติดตามเงิน/ตรวจสอบ) · CollectionsController · PayoutEligibility ·
VolumeAccumulator · InstallmentSchedule · ReportController::paymentHistory (+ payee/pay_mode/ยอดแยก) · CollectionsAuditPayments
```

ยอดชำระ (credit) = เงินที่รับ + ส่วนลด/ค่าคอมที่หัก · ยอดขายสะสม = เงินที่รับ + ค่าคอมที่หัก (ส่วนลดไม่นับ) · `PolicyPayment` มี global scope ซ่อนรายการที่ยกเลิกในทุก query แบบ Eloquent ส่วน query ดิบเพิ่มเงื่อนไข `voided_at IS NULL` ทุกจุด

## 7. รายการตรวจรับ (UAT)

1. เปิดกรมธรรม์ที่ยังไม่ชำระ → การ์ดแสดงเบี้ยเต็ม ค้างเต็ม ป้าย "ยังไม่ชำระ" · กด "บันทึกการชำระเงิน" ช่องเงินถูกเติมเป็นยอดค้าง
2. แนบสลิป (ไฟล์ใหญ่ >10 MB หรือชนิดอื่นต้องถูกปฏิเสธพร้อมข้อความ) → บันทึก → ป้ายเป็น "ชำระครบแล้ว" · ตารางมีรายการ + ปุ่มดูสลิปเปิดไฟล์ได้
3. ค่าคอมของตัวแทน/upline ขึ้นในหน้าค่าคอม · ยอดขายสะสมเดือนนั้นเพิ่ม · หน้าติดตามเงินไม่แสดงกรมธรรม์นี้แล้ว
4. กด "ยกเลิกรายการ" โดยไม่ใส่เหตุผลต้องถูกเตือน · ใส่เหตุผลแล้ว รายการถูกขีดฆ่า ยอดกลับเป็นค้างเต็ม ค่าคอมที่ยังไม่เข้ารอบถูกย้อน
5. โหมด "จ่ายหักคอมมิสชั่น": ช่องค่าคอมที่หักถูกเติมจากกรมธรรม์ · บันทึกแล้วลูกค้าไม่ค้าง · หน้ารอบจ่ายของตัวแทนมี "รายการหักค้าง −ค่าคอมที่หัก" · พยายามหักเกินค่าคอมตัวแทนต้องถูกปฏิเสธ
6. โหมด "จ่ายมีส่วนลด": ลูกค้าไม่ค้างส่วนลด
7. "ชำระให้บริษัทประกัน": รายการมีป้าย "จ่ายตรงบริษัทประกัน" · การ์ดแยกยอดเข้า InsureHub / บริษัทประกัน · รายงานประวัติการชำระแยกยอดเช่นกัน
8. กรมธรรม์สถานะ "ออกกรมธรรม์" (issued) → หลังรับเงิน สถานะเป็น "มีผล" (active)
9. กรมธรรม์ยกเลิก/หมดอายุ → ปุ่มปิดพร้อมเหตุผลบนหน้า · API ปฏิเสธ
10. ผู้ใช้ไม่มีสิทธิ์ `payments.record` → ปุ่มปิด · ไม่มีสิทธิ์ `payments.void` → ไม่เห็นปุ่มยกเลิกรายการ
11. บันทึกซ้ำวัน+ยอดเดียวกันภายใน 10 นาที และยอดเกินเบี้ย ต้องมีกล่องถามยืนยัน
12. รายการที่ค่าคอมเข้ารอบจ่ายแล้ว → ยกเลิกไม่ได้ ขึ้นข้อความ "ค่าคอมอยู่ในรอบจ่ายแล้ว"
