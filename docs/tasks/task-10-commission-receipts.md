| เปิดแก้ / ไม่มีค่าคอม | ต้องใส่เหตุผลทุกครั้ง (เลิกใส่ค่าเริ่มต้นเอง) · เปิดแก้ล้างยอดรับ วันที่ รอบ และสาเหตุ แล้วคำนวณสถานะจากยอดตามบริษัทใหม่ · เตือนถ้ากรมธรรม์นั้นจ่ายค่าคอมตัวแทนไปแล้ว |
| รอบ statement | เดือนของ statement + ยอดรวมตาม statement · เทียบกับยอดที่ยืนยันรับเข้ารอบนั้น (จำนวน, ยอดรับ, ส่วนต่าง) · ดาวน์โหลดไฟล์แนบผ่าน token (เดิมเปิดแล้ว 401) · แนบ csv ได้เพิ่ม |
| สรุปผล | การ์ด **สรุปเคสยอดไม่ตรงตามสาเหตุ** (จำนวน + ส่วนต่างรวม) + เคสที่ยังไม่ระบุสาเหตุ · รายการปรับปรุงรับแล้ว/ค้าง · ค่าคอมตัวแทน: ต้องจ่าย (รวม rider) เทียบกับ **จ่ายแล้วเฉพาะค่าคอมพื้นฐาน** + แยกค่าแนะนำ/ค่าบริหาร · ตัวกรองเดือนเดียวกับหน้าหลัก |
| ส่งออก | CSV (UTF-8 BOM, กันสูตร Excel) ทุกแถวตามตัวกรอง พร้อมสาเหตุ รายละเอียด และข้อสังเกต สำหรับเก็บเคส UAT |
| สิทธิ์ | `receipts.view` ดู · `receipts.record` คีย์/รับ/ไม่มีค่าคอม/รายการปรับปรุง/รอบ statement · `receipts.reopen` เปิดแก้ · บทบาท **finance** ได้ทั้ง 3 · executive ดูได้ · เมนูซ่อนเมื่อไม่มีสิทธิ์ดู (เดิมไม่ตรวจสิทธิ์เลย ตัวแทนเรียก API กด "รับแล้ว" ได้) |

## 3. การไหลของข้อมูล

```
รับค่าคอม (บริษัท + เดือน)  GET commission-receivables?insurerId=&monthFrom=&monthTo=&includeOutstanding=
   └─ seedReceivables: INSERT … SELECT (MAIN ทุกกรมธรรม์ ≤ สิ้นเดือน, OV เมื่อ calculated_ov > 0)
        ระบบเดิม + com_rec_check = Complete → Received (source legacy)
   └─ แถว + hints (ยกเลิก / สลักหลัง×อัตรา / ไม่มีค่าคอมในกรมธรรม์ / อัตราตามบริษัท) + suggestedReason

คีย์ยอด: PATCH {id}/review · POST bulk-review (lock เรียง id, version ต่อแถว, all-or-nothing)
วางจาก Excel: POST statement-match {insurerId, lines[{ref, amount}]} → matched / notFound / otherInsurer / alreadyClosed / duplicates → bulk-review
ยืนยันรับ: POST {id}/receive · POST bulk-receive {receivedDate, receiptBatchId, items[{id, version, receivedAmount, diffReason, diffNote}]}
   ต่างเกิน 0.01 → ต้องมี diffReason (other ต้องมี diffNote) · รอบต้องเป็นบริษัทเดียวกัน
   ADJ ยกเลิก (ติดลบ) รับแล้ว → policies.cancel_check_carrier_deduct = done + audit
รายการปรับปรุง: POST adjustments {policyId, kind, expectedAmount, policyEventId?, note} (line_no 1..n) · GET adjustments/suggest
เปิดแก้: POST {id}/reopen (receipts.reopen) → ล้างยอดรับ/วันที่/รอบ/สาเหตุ · meta.warning ถ้าจ่ายตัวแทนแล้ว

PayoutEligibility (งาน 9): อ่านสถานะ MAIN line 0 เหมือนเดิม · CommissionPayoutService ข้าม imported_from_legacy ในบรรทัด base

ติดตามเงิน: PremiumDue::due = ผลรวมงวด ถ้ามี ไม่งั้น max(main+compulsory, total_premium_paid + สลักหลัง)
            PremiumDue::paid = รายการชำระจริง หรือ (ระบบเดิม + ไม่มีรายการชำระ) = ครบ
บันทึกชำระ: lock กรมธรรม์ → ซ้ำภายใน 10 นาที (วันที่+ยอด+งวด) หรือซ้ำในชุดเดียวกัน → 409 payment_duplicate
            ยอดรวมเกินที่ต้องชำระ > 1 บาท → 409 payment_overpay · หน้าจอถามยืนยันแล้วส่ง confirmDuplicate / confirmOverpay
```
